# GLOSSARY

Единый словарь проекта. Термины используются в коде, БД, API, UI и документации
**в одном и том же смысле**. При расхождении терминов — это баг.

> Правило именования в коде: английский, PascalCase для типов, snake_case для полей.

---

## 1. Предметная область

| Термин | Определение |
|---|---|
| **Mask Project** | Центральная сущность системы — полное цифровое описание производства физической маски. Не файл, а объект с историей, версиями и производственными параметрами. Идентификатор вида `MASK-000127`. |
| **Digital Passport** | Цифровой паспорт дизайна = Mask Project в его полной форме (дизайн + модель + деталь + геометрия + масштаб + слои + параметры + файлы + инструкция). Метафора воспроизводимости. |
| **Source Design** | Исходное изображение или вектор, загруженное пользователем либо взятое из каталога. |
| **Object Model** | Запись в каталоге объектов: бренд, модель, поколение, год, конкретная деталь. |
| **Part** | Конкретная деталь объекта (капот, боковина шлема, верхняя дека гитары). |
| **Object Geometry** | Геометрическое описание детали: размеры, границы, кривизна, запрещённые зоны, параметры развёртки. |
| **Fit** | Процесс адаптации дизайна под геометрию детали. |
| **Reproduction** | Повторное производство маски из существующего Mask Project без повторного проектирования. |

## 2. Геометрия

| Термин | Определение |
|---|---|
| **Path** | Упорядоченная последовательность вершин и сегментов. Может быть замкнутой или открытой. |
| **Contour** | Замкнутый контур — граница сплошной области. |
| **Island** | Островок: связная область маски, полностью окружённая вырезом (cut), не соединённая с остальной плёнкой. |
| **Hole** | Отверстие внутри контура: область **без** материала внутри сплошного контура. |
| **Bridge** | Соединительный элемент между островком и основной плёнкой (или между двумя элементами), удерживающий островок от выпадения при снятии маски. |
| **Tab** | Удерживающий «язычок» на мосте. |
| **Cut** | Резаная контурная линия — граница, по которой нож/лазер отделяет материал. |
| **Crease / Score** | Линия сгиба (для работы с плоскими листами и перегибанием маски). |
| **Island threshold** | Минимальная площадь островка, ниже которой он признаётся непригодным. |
| **Min Line Width** | Минимальная ширина элемента маски, которую можно надёжно вырезать и оставить на детали. |
| **Min Gap** | Минимальный зазор между соседними вырезами, ниже которого возникает риск слияния или разрыва плёнки. |
| **Corner Radius** | Минимально допустимый радиус внутреннего угла (защита от концентрации напряжений и обрывов плёнки). |
| **Peelability** | Способность маски быть нанесена, выдержана и снята без отрыва покрытия детали. |
| **Registration** | Точность и способ совмещения слоёв между собой и с деталью. |
| **Registration Mark** | Метка совмещения на частях маски после разбиения. |
| **Kerf** | Ширина реза, выедаемая ножом или лазером. |
| **Weed** | Процесс удаления лишнего (внутренних) материала после вырезания. |

## 3. Слои

| Термин | Определение |
|---|---|
| **Visual Layer** | Слой в исходном изображении — цветовое/семантическое разделение картинки. |
| **Physical Layer** | Одна физическая маска = одна операция покраски: отдельный файл, отдельный цикл нанесения, отдельный цвет. **Главная единица производства.** |
| **Mask Layer** | Physical Layer, привязанный к геометрии, порядку нанесения и производственным параметрам. |
| **Layer Graph** | Граф зависимостей между слоями: `under`, `over`, `intersects`, `bridges`, `mask_for`. |
| **Layer Order** | Топологический порядок нанесения, выведенный из Layer Graph. |
| **Layer Split** | Разделение одного визуального элемента на несколько физических слоёв (тень, база, блик). |
| **Layer Merge** | Объединение нескольких визуальных элементов в один физический слой. |
| **Shim / Spacer** | Промежуточный слой подложки, отвечающий за зазор между слоями для контроля наложения краски. |
| **Stencil Layer** | Слой, закрывающий область от нежелательного нанесения (обратная маска). |
| **Overprint** | Область наложения красок слоёв — влияет на конечный цвет. |

## 4. Производство

| Термин | Определение |
|---|---|
| **Material Profile** | Профиль материала маски: минимальные размеры, радиусы, адгезия, снимаемость, допустимая температура, цена. Данные, не код. |
| **Plotter Profile** | Профиль режущего оборудования: ширина ножа, угол лезвия, рабочее поле, скорость, усилие, формат команды. |
| **Cutting Profile** | Объединённый набор ограничений конкретной связки «материал + оборудование». |
| **Manufacturing Rule** | Атомарное проверяемое правило (min-line-width ≥ 0.8 mm и т. п.) с параметрами. |
| **Rule Set** | Набор правил для проверки, сгенерированный из профилей + режима производства. |
| **Manufacturing Validator** | Детерминированный компонент, выдающий вердикт `PASS / WARNING / FAIL` по проекту и профилям. |
| **Manufacturable** | Проект, прошедший валидацию для заданных профилей. |
| **Auto-Fix** | Автоматическое устранение нарушений (расширение элемента, добавление моста, слияние, удаление шума). |
| **Auto-Simplify** | Снижение сложности геометрии с контролем падения fidelity. |
| **Fidelity** | Измеримое визуальное сходство результата с исходным изображением. |
| **Nesting** | Раскладка частей маски в пределах рабочего поля оборудования с минимизацией отходов. |
| **Tile** | Часть маски, помещающаяся в рабочее поле при разбиении. |
| **Cut Path** | Финальная траектория реза, генерируемая Export Engine. |
| **Production Manifest** | Машиночитаемый перечень всех производственных артефактов проекта с хешами и параметрами. |
| **Proof** | Физический или цифровой контрольный образец. |

## 5. Система и процесс

| Термин | Определение |
|---|---|
| **Mask Engine** | Технологическое ядро: преобразование изображения/вектора в производственный Mask Project. |
| **Mask Studio** | Редактор и визуальный интерфейс поверх ядра. |
| **Engine Run** | Один прогон ядра с зафиксированными входом, профилями и версией движка. |
| **Candidate** | Предложенное AI или пользователем разбиение на слои/элементы, ещё не прошедшее валидацию. |
| **Accepted** | Кандидат, прошедший Manufacturing Validator и записанный в проект. |
| **Snapshot** | Замороженная копия профиля или проекта, используемая для воспроизводимости. |
| **Golden Test** | Тест на эталонном проекте, фиксирующий ожидаемый выход ядра. |
| **ADR** | Architecture Decision Record — зафиксированное техническое решение с контекстом и последствиями. |
| **Physical Validation** | Прогон реально вырезанной и нанесённой маски на реальном объекте. |
| **P-Stage** | Приоритетный этап разработки (см. `13_ROADMAP/ROADMAP.md`). |

## Нечёткие термины — запрещено

Слова **«слой»**, **«качество»**, **«похоже»**, **«производимый»**, **«точный»** не
допускаются в технической документации без уточняющего квантора
(«Physical Layer 03», «min width ≥ 0.80 mm», «fidelity 0.91»).

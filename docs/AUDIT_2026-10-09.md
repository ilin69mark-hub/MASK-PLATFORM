## 2. Расхождения между документами и кодом

Это находка номер один: у проекта **две системы учёта**, и они разошлись.

### 2.1 Роадмап недооценивает сделанное

`ROADMAP.md` §7, «Фактическое состояние» Stage 5, утверждает:

> `DXF`, `PLT`, `PDF` и `per_project` раскладка — нет.

По коду: `engine/export/src/dxf.rs`, `plt.rs`, `manifest.rs` — `to_dxf`, `to_plt`,
`from_dxf`, `build_manifest`, все задействованы в CLI (`cut_dxf`, `cut_plt`).
Реализованы **DXF и PLT**. Не реализован только PDF. Утверждение роадмапа на три
пункта пессимистичнее факта.

### 2.2 Роадмап не замечает сделанные профили

`ROADMAP.md` §6, задача 4.1 «Профили как данные + версии» — не помечена выполненной.
По коду `engine/profiles/` — `MaterialProfile` с физическими минимумами,
`PlotterProfile` + `Blade` (включая `kerf_mm`), `validate()`, и три профиля в
`data/`: `knife-25mm.v2.json`, `matte-vinyl-090.v4.json`,
`matte-vinyl-090-experiment.v1.json`. То есть **ровно те три, что называет
исследование** в GEOM-060. Задача выполнена.

### 2.3 Документ модуля обещает несуществующую раскладку

`engine/nesting/src/lib.rs:9` — «Scope: `fixed_grid` and `strip`». Публичная функция
одна: `fixed_grid` (`nesting/src/lib.rs:147`). `strip` не реализована. Комментарий
врёт в том же дереве, которое он описывает.

### 2.4 Собственная ошибка аудита, исправленная

В разборе GEOM-блока я утверждал, что `GEOM-060` — «единственная реальная работа,
которой действительно нет». Это неверно: профили реализованы (§2.2). Ошибка в
сторону недооценки сделанного — она опаснее обратной, потому что ведёт к
дублированию существующего.

## 3. Разбор блока GEOM — что всё-таки нужно

Сверено с кодом, по каждой из девяти задач.

| | Задача | Что в коде | Нужно ли |
|---|---|---|---|
| 020 | API ядра: `shape_centroid`, `shape_moment_of_inertia`, `contour_centroid` | **отсутствуют**, ноль вхождений | ❌ **нет** — см. §3.1 |
| 030 | libigl LSCM FFI, 3D→2D UV | нет UV-параметризации вовсе | ❌ нет: Stage 7 по роадмапу — ортофото + 2.5D, не UV-развёртка |
| 040 | bridging / kerf / despeckle из Cutter | `bridge_unanchored`, `offset_shape`, `unanchored_islands`, `drop_small_regions` | ✅ **сделано** |
| 050 | декомпозиция слоёв, UI мостов | алгоритмическая база есть, редактора слоёв нет | ❌ нет: это Studio, не геометрия |
| 060 | профили Material/Cutter/Paint | Material ✓, Cutter ✓, стандартные профили ✓; **PaintProfile ✗** | ⚠️ **частично** — см. §3.2 |
| 070 | Go C ABI / gRPC | каталога `services/` нет, A1 соблюдён | ❌ противоречит A1 |
| 080 | MVP mesh → UV → pattern → SVG | держится на UV и PDF/SVG, которых нет в этой форме | ❌ недостижимо |
| 090 | продакшн-харднинг | golden-тесты и `make check` есть; property-based и leak-checks нет | ❌ нет: `make check` уже шире |
| 100 | интеграция Studio | зависит от всей цепочки | ❌ недостижимо |

**Вывод: из блока GEOM не нужно брать ничего.** Это не упущенный план — это
описание вещей, которые проект затем построил другими путями (040 → мосты и островки,
060 → `mask-profiles`). Единственное, что в блоке не построено, — `PaintProfile`.

### 3.1 Почему `centroid` и `moment_of_inertia` не берём

Они отсутствуют, и в прошлых разборах я предлагал их забрать. Проверил
потребителя — **его нет**:

* плотность слоя (T-13) считается как `число элементов / площадь bbox`
  (`validate/src/lib.rs:590`), а не через центр масс;
* регистрационные метки берутся из якорей раскладки (`export/src/manifest.rs:292`),
  а не из центроидов;
* раскладка размещает плитки по `fixed_grid`, центроид не участвует.

Добавить эти функции — значит добавить API без потребителя. Проект такое уже
критиковал в собственном бэклоге («задачи без места в порядке не имеют
зависимостей»). Не берём.

### 3.2 Единственное, что стоит взять: `PaintProfile`

И то не сейчас. `PaintProfile` (opacity, layer_order, bleed_compensation, dry_time)
нужен не сам по себе, а как источник данных для **инструкции из проекта**
(`ROADMAP.md` 5.6) — инструкция сейчас не генерируется вовсе (в коде 0 реализаций,
только упоминания в комментариях). Строить профиль до потребителя = повторять
ту же ошибку. Правильная последовательность: инструкция → потом профиль.

## 4. Настоящая дыра: Stage 7 не имеет плана

Ни роадмап, ни GEOM-блок не описывают, **как плоский паттерн садится на изогнутую
деталь**. Роадмап (§9) даёт восемь задач и ни одной с критерием проверки кода;
GEOM-блок предлагает libigl UV-развёртку, но роадмап же выбрал другое — ортофото и
2.5D height field. Это единственное место, где продуктовая идея и её реализация
расходятся, и оно не имеет владельца.

## 5. Пробелы по направлениям

### 5.1 Производство (Stage 5) — добить путь до комплекта

PDF (`ROADMAP` 5.4), инструкция из данных проекта (5.6), ZIP-архив (5.8),
round-trip SVG→геометрия (критерий выхода 5.1 — `from_svg` не существует, при том
что `from_dxf` есть). Ни одно из этого в трекере не заведено.

### 5.2 Студия (Stage 6) — производительность и слепое пятно верификации

Бюджет кадра 16 мс укладывается на 100–200 регионов (`PERF-002`, `PERF-003`).
Кривая линейна — это не патологический O(n²), но редактор живёт в сотнях
регионов. Второе: **UI проверен скриншотами и snapshot'ами, а не кликами** —
browsermcp `click`/`hover` стабильно таймаутится. Редактор вершин, который я
чинил (BUG-022), не проверен настоящим взаимодействием.

### 5.3 Инфраструктура решения

`BLOCK-002` — модели детерминизма и версионирования без ADR. Пока их нет,
нельзя выполнить критерий Stage 5 «два экспорта дают идентичные хеши» как
требование к версии движка, хотя golden-хеши уже есть.

### 5.4 Атрибуция

Технический аудит лицензий сделан (`GEOM-010`, 53 зависимости, `make licenses`
падает при пропуске). Юридическое заключение — не получено, остаётся на владельце.

## 6. Рекомендации по приоритету

1. **Физический прогон** (`BLOCK-001`) — единственное, что двигает продукт.
   Программная часть готова и проверена.
2. **Инструкция из данных проекта** — без неё комплект неполон, и это потребитель
   для `PaintProfile`, который закроет GEOM-блок окончательно.
3. **Round-trip SVG** — без импортёра критерий выхода Stage 5 не выполняется вовсе,
   а `from_dxf` уже показывает, что путь рабочий.
4. **ADR детерминизма и версионирования** — разблокирует формулировку критериев.
5. **План Stage 7** — до первой физической попытки; иначе после прогона выяснится,
   что привязки к детали нет, и это будет дороже.
6. **Верификация UI кликами** — обойти через вызов обработчиков в тесте, раз
   драйвер не работает.
7. **Расхождения документов** (§2) — закрыть дешевле всего, пока контекст свежий.

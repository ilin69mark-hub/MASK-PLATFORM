# ADR-0003 · Язык и рантайм геометрического ядра

- **Status**: ACCEPTED
- **Date**: 2026-10-05
- **Deciders**: Founder / CTO
- **Affects**: `engine/kernel`, `engine/engine`, `engine/wasm`, CI, ADR-0004, ADR-0013
- **Principles**: P-03 (геометрия — источник истины), P-07 (ядро независимо от веба), P-08 (воспроизводимость), P-11 (технологии без моды)
- **Supersedes**: —

## Context

`SYSTEM_ARCHITECTURE.md` зафиксировал разделение: вычислительное ядро — Rust,
системный слой — Go. Это было обосновано профилем нагрузки, но **не проверено**,
а `ADR_PROCESS.md` требует технического обоснования до реализации.

Кроме языка нужно было выбрать offset и boolean-операции. Это самое крупное
техническое решение ядра: собственная реализация polygon offset — недели работы
с численно хрупкой геометрией, а ошибка здесь даёт тихую порчу масок, которую
не поймает никакой тест на отсутствие паник.

Поэтому выбор сделан **измерением, а не рассуждением**: собран одноразовый
пробник `spike/geometry-spike`, который проверяет кандидатов по критериям
приёмки из этого ADR.

### Кандидаты и что показало исследование реестра

| Кандидат | Версия | Активность | Ключевой факт |
|---|---|---|---|
| `i_overlay` | 9.0.0 | 130 релизов, без yanked | Чистый Rust, `#![no_std]`, **явный целочисленный движок** `i16/i32/i64`, offset/stroke, simplify, fill rules |
| `clipper2` | 0.6.0 | 16 релизов | FFI-обвязка над C++ (`clipper2c-sys`) |
| `geo-booleanop` | 0.3.2 | 7 релизов | Чистый Rust, но без offset |

`clipper2` отпадает не по качеству, а по **сборке**: зависимость от C++ FFI
требует C-тулчейна, emscripten или внешней сборки и делает цель
`wasm32-unknown-unknown` недостижимой без значительных затрат. ADR-0013
требует, чтобы ядро работало и в браузере, поэтому C++ FFI в ядре недопустим.

## Decision

**1. Геометрическое ядро пишется на Rust. Toolchain закреплён в
`rust-toolchain.toml` (`channel = "stable"`).**

**2. Offset и boolean-операции выполняются библиотекой `i_overlay`.**
Собственная реализация не принимается.

**3. Все вызовы boolean и offset проходят через **явный целочисленный
движок** с фиксированным масштабом:**

```text
engine = i64
scale  = 1 / CANON_QUANTUM_MM = 1e4
```

Используется `overlay_with_fixed_scale_as::<i64>(...)`, **не** ненадёжные
(`Result`-возвращающие) варианты. Это следствие измеренного поведения,
см. «Отрицательные результаты» ниже.

**4. Собственная логика ядра** (измерения, канонизация, упрощение, мосты,
проверки) остаётся нашей и не делегируется библиотеке.

## Measured results

Пробник: `spike/geometry-spike`, сетка `1e-4 мм`, движок `i64`, Rust 1.99.0.
Все числа ниже — измерены, воспроизводятся повторным запуском.

### Критерий 1 — offset / widen с точным дельтой

Центральная линия длиной 100 мм, целевая ширина полосы, заглушки butt, скругления miter:

| Цель | Площадь, мм² | Измеренная ширина | Integer vs Float |
|---|---|---|---|
| 0.80 мм | 79.999995 | 0.800000 | хеш совпал |
| 0.42 мм | 42.000008 | 0.420000 | хеш совпал |
| 0.05 мм | 4.999995 | 0.050000 | хеш совпал |
| 0.01 мм | 0.999999 | 0.010000 | хеш совпал |

Отклонение площади ≤ 8·10⁻⁶ мм², то есть ошибка ширины ≈ 8·10⁻⁸ мм —
на три порядка ниже `CANON_QUANTUM_MM = 1e-4 мм`.

**Вердикт: PASS.** Операция «расширить элемент» из Auto-Fix реализуема.

### Критерий 2 — boolean на наших формах

| Случай | Ожидаемая площадь | Измерено | Результат |
|---|---|---|---|
| Пересекающиеся полосы (X), union | 39.000000 | 39.000000 | точное совпадение |
| Пересекающиеся полосы, intersection | 1.000000 | 1.000000 | точное |
| Соприкасающиеся рёбра, union | 100.000000, 1 shape | 100.000000, 1 shape | **слились в одну область** |
| Совпадающие контуры, union | 50.000000 | 50.000000 | точное |
| Вложенный контур с отверстием | 301.000000 | 301.000000, 2 shapes, 1 hole | отверстие сохранено |
| Самопересечение (бабочка) | 50.000000 | 50.000000, 2 shapes | разрешено в 2 треугольника |
| Острый угол 10° | 34.730000 | 34.730000 | точное |

**Вердикт: PASS.** Все семь форм, взятых из целевого класса графики
(переплетения, узлы, петли, вложенность), обработаны без потерь.

### Критерий 3 — детерминизм

| Проверка | Результат |
|---|---|
| Повтор одной операции ×5 | хеши идентичны |
| Движок `i32` против `i64` | разница площади 0.000000000 мм², **хеш тот же** |
| Два отдельных процесса | вывод **побайтово идентичен** (`diff` пуст) |
| `MathMode::Integer` против `Float`, скруглённые соединения | **хеши РАЗЛИЧАЮТСЯ** |

**Вердикт: PASS с одним ограничением.** Математический режим влияет на
результат и обязан быть закреплён, а не выбираться по месту вызова.

### Критерий 4 — отсутствие паник

| Вход | Поведение |
|---|---|
| `NaN` в координате | `Err(InvalidRect(CoordinatesOutOfRange))` — паники нет |
| `INFINITY` в координате | `Err(InvalidRect(CoordinatesOutOfRange))` — паники нет |
| Пустой контур, одна точка, дубли, нулевой сегмент | значение возвращено, паники нет |
| Обе области пусты | 0 областей, паники нет |
| Координаты 10¹² мм | принято (бюджет координат велик) |
| 400 итераций случайного sweep (seeded LCG) | **0 паник**, 400 успешных результатов |

**Вердикт: PASS.** Важно: отказ приходит через `Result` только на
fixed-scale API. Infallible-варианты библиотеки **паникуют** при выходе
за границы — их использовать нельзя.

### Критерий 5 — компиляция в wasm32

`cargo build --target wasm32-unknown-unknown` — успешно, вся цепочка
зависимостей (`i_float`, `i_shape`, `i_tree`, `i_key_sort`, `i_overlay`)
собирается для wasm32.

**Вердикт: PASS.** Требование ADR-0013 выполнимо.

## Отрицательные результаты

Эти находки важнее положительных — каждая влияет на дизайн ядра.

| # | Находка | Следствие для проекта |
|---|---|---|
| N-1 | `MathMode::Integer` и `Float` дают **разные** хеши при скруглённых соединениях и заглушках | `MathMode` фиксируется в конфигурации движка и **никогда** не выбирается по месту вызова. Значение записывается в manifest |
| N-2 | Infallible API библиотеки **паникует** при выходе за границы координат | Использовать только `*_with_fixed_scale*` и `*_as::<I64>`; infallible-обёртки запрещены линтером |
| N-3 | Бюджет координат шире наших потребностей: 10¹² мм принимается | Ядро само проверяет границы по размерам детали (`part bbox + margin`) до вызова библиотеки |
| N-4 | **Коллапс тонкого элемента не происходит автоматически**: stroke линии с шириной 0.00001 мм всё равно даёт полосу площадью 0.001 мм² | Правило «элемент тоньше порога → нарушение» **нельзя делегировать библиотеке**. Реализуется нами через измерение и сравнение с порогом профиля (`TOPOLOGY_ENGINE.md` §3) |
| N-5 | Offset полигона (`OutlineOffset`) поддерживает только целочисленную математику; `StrokeOffset` — обе | Для задачи «расширить полосу» используется `StrokeOffset`; `OutlineOffset` ограничен Integer |
| N-6 | Инвариант ориентации библиотеки: внешний контур CCW, отверстия CW | Площадь считается **знаковой** суммой (shoelace без `abs`), иначе отверстия прибавляются. Наша функция измерения обязана это учитывать |

## Alternatives

### A. Собственная реализация offset и boolean

- **Плюсы**: полный контроль; ноль внешних зависимостей; точная настройка
  под наши формы.
- **Минусы**: robust polygon offset с коллапсом на острых углах — недели
  работы и известная численная хрупкость; self-intersecting вход потребует
  собственного распознавания; риск тихих ошибок именно там, где цена ошибки
  максимальна (порча физической маски).
- **Стоимость**: задержка Stage 2 на 3–6 недель при неопределённом результате.

### B. `clipper2` (FFI над Clipper2 C++)

- **Плюсы**: проверенный временем алгоритм Clipper2, широко используется в CAM.
- **Минусы**: зависимость от C++ toolchain; **не собирается в wasm32 без
  emscripten**; 16 релизов — экосистема моложе; привязка к ABI C++.
- **Стоимость**: блокирует ADR-0013 и усложняет сборку.

### C. `geo-booleanop`

- **Плюсы**: чистый Rust, зрелый API, используется в экосистеме `geo`.
- **Минусы**: **нет offset** — а это наша операция авто-фикса; 7 релизов,
  фактически без развития.
- **Стоимость**: потребовался бы второй транзитивный offset.

### D. Только f64-режим без целочисленного движка

- **Плюсы**: чуть меньше кода на границе.
- **Минусы**: теряется измеренное совпадение хешей `i32`/`i64`; автоматическое
  масштабирование скрывает выбор сетки, а нам нужен явный контроль.
- **Стоимость**: более слабая гарантия детерминизма.

## Consequences

### Positive

- Главный технический риск Stage 2 снят измерением, а не верой.
- Получен сильный determinism: `i64` + фиксированная сетка + закреплённый
  `MathMode` дают побайтовую воспроизводимость, измеренную на двух процессах.
- Требование браузерного ядра (ADR-0013) остаётся достижимым.
- Уточнены три обязанности нашего кода, которые библиотека **не** выполняет:
  проверка границ координат, коллапс тонких элементов, знаковая площадь.

### Negative / Trade-offs

- `i_overlay` 9.0.0 требует Rust ≥ 1.88 — toolchain не может быть старым.
- Внешняя зависимость в ядре: обновление библиотеки может изменить хеши.
  Это ожидаемо и фиксируется через `engine_version`.
- Три измеренных ограничения (N-1…N-6) надо закрепить линтерами и тестами,
  иначе они проявятся как тихие баги.

### Follow-up

- Линтер-правило: запрет infallible-вариантов `i_overlay` (N-2).
- Тест: `MathMode` из конфигурации, а не из аргумента вызова (N-1).
- Тест: коллапс элемента тоньше порога — наша логика, не библиотечная (N-4).
- Знаковая площадь как инвариантный тест на ориентацию контура (N-6).
- ADR-0004 дополнен: integer-движок — это дисциплина границы вызова,
  а не смена внутреннего представления.

## Validation

| Проверка | Критерий | Факт |
|---|---|---|
| Offset с точным дельтой | ширина ≥ цели минус `MEASURE_EPS_MM` | отклонение 8·10⁻⁸ мм — **PASS** |
| Boolean на 7 формах | площади совпадают с аналитическими | все семь точны — **PASS** |
| Детерминизм в процессе | два процесса дают идентичный вывод | `diff` пуст — **PASS** |
| Совпадение движков | `i32` и `i64` дают одинаковый хеш | совпали — **PASS** |
| Отсутствие паник | 0 паник на 400 итерациях sweep | 0 — **PASS** |
| wasm32 | зависимости собираются под цель | собрано — **PASS** |
| Ограничения зафиксированы | N-1…N-6 отражены в ADR и в тестах | отражены здесь, тесты — в Stage 2 |

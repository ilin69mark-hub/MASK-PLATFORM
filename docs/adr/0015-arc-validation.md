# ADR-0015 · Дуги валидируются как часть контура

- **Status**: ACCEPTED
- **Date**: 2026-10-06
- **Deciders**: Founder / CTO
- **Affects**: `engine/kernel` (`geom.rs`, `canonical.rs`, `hash.rs`), `engine/validate`, `engine/wasm`, ADR-0004, ADR-0014
- **Principles**: P-03 (геометрия — источник истины), P-05 (пороги — из профиля), P-09 (ошибка говорит, что делать), P-04 (визуальный слой ≠ физический)
- **Supersedes**: —

## Context

Кривые появились в `Contour` как `Vec<ArcSegment>` — хордальное представление: дуга
называет два уже существующих индекса в `points` и описывает кривую между ними.
Поле добавлено так, чтобы ни один существующий контур не изменил смысла: пустой
список дуг — это «все рёбра прямые».

Так и случилось. Пока не столкнулось с тем, что **дуги не проверяются вообще**.

`Contour::validate` (`kernel/src/geom.rs:319-334`) проверяет количество точек,
их конечность и границы — и не обращается к `self.arcs`. `ArcSegment` получает
`Deserialize` без единой проверки: `radius`, `from` и `to` принимаются как есть.
Ядро при этом заявляет обратное в самом себе:

> `kernel/src/lib.rs:3-4` — «Unit is millimetres throughout (ADR-0004). `NaN` and
> `Inf` are forbidden in stored geometry; construction rejects them rather than
> propagating them.»

Это утверждение верно для точек и неверно для дуг. Три конкретных следствия,
каждое воспроизведено на настоящем wasm-артефакте, а не выведено из чтения кода:

**1. Паника вместо нарушения.** `validate/src/lib.rs:653-654`:

```rust
if has_curves(&layer.geometry) {
    let radius = min_corner_radius(&layer.geometry).expect("curves exist");
```

`has_curves` истинно при любом непустом `arcs`. `min_arc_radius` фильтрует
`r > 0.0` и возвращает `None`, если ни один радиус не положителен. Контур с дугой
радиуса `0.0` даёт `expect` на `None`. Проектный документ с таким контуром
приводит к:

```
THREW: RuntimeError: unreachable
```

Это противоречит инварианту самого крейта (`validate/src/lib.rs:268`): «Never
panics: every problem becomes a violation». В wasm паника не бросает исключение —
она **убивает модуль**: после неё инстанс непригоден, и следующий вызов из
редактора тоже падает. В браузере это отказ редактора целиком.

Путь достижим из `validate_project` (`wasm/src/lib.rs:149`), документированного
как «the same Mask Project JSON the server reads» (`wasm/src/lib.rs:145-148`).
`extract_layers` (`wasm/src/lib.rs:414-419`) десериализует геометрию **без**
`validate_strict`, в отличие от `measure_layer_inner` (`wasm/src/lib.rs:190-192`),
который проверяет.

**2. Тихая потеря дуги.** Проверено на артефакте:

| вход (контур из 4 точек) | `area_mm2` | `content_hash` | path data |
|---|---|---|---|
| без дуг | `100.0000` | `sha256:51e9918def336b5af` | `M…L…L…L…Z` |
| `arc {from:0, to:1, r:5}` | `171.4049` | `sha256:0ec0ec2993088` | `M…C…L…L…Z` |
| `arc {from:0, to:3, r:7.07}` | `100.0000` | `sha256:51e9918def336b5af` | `M…L…L…L…Z` |
| `arc {from:0, to:99, r:5}` | `100.0000` | `sha256:51e9918def336b5af` | `M…L…L…L…Z` |

Строки 1, 3 и 4 — **один и тот же digest**: фигура, объявлявшая кривую, и
многоугольник без неё неразличимы. Это ровно тот класс дефекта, который уже чинили
в `cfb31ae` («the hash finally sees the curves»): тогда хеш игнорировал все дуги,
теперь — те, что не заменяют ровно одно ребро.

#### Три потребителя, одно правило

Дугу читают четыре места, и важно, что они **согласованы** между собой, а не
противоречат друг другу:

| Потребитель | Что требует | Где |
|---|---|---|
| `resolved_arcs` | `to == (from + 1) % n` | `geom.rs:249-267` |
| `flattened` | `arc.to == next` | `geom.rs:313` |
| `to_path_data` | берёт список из `resolved_arcs` | `canonical.rs:130` |
| площадь / периметр | берут список из `resolved_arcs` | `measure.rs:39`, `:126` |

То есть «одна дуга — одно ребро» уже было фактом; оно просто нигде не
проверялось, и всё, что этому не соответствует, исчезало без следа. Решение не
вводит нового правила — оно делает существующее проверяемым.

Расходится **документация типа**: `ArcSegment` говорит «`to` is exclusive, so the
run is `from .. to`» (`geom.rs:107-111`), то есть допускает многоточечный прогон.
А `measure.rs:725-748` — тест многоточечной дуги — вызывает `arc_sweep` напрямую с
явно разрешёнными точками, минуя конвейер. То есть математика многоточечные прогоны
умеет, а конвейер — нет, и тест этого не замечает. Это расхождение зафиксировано
отдельной задачей (`BUG-010`), а не решёно здесь: выбор «разрешить прогоны» против
«уточнить контракт типа» — вопрос доменной модели, и он не входит в исправление
достижимой паники.

**3. Переполнение `usize`.** `flattened` (`geom.rs:282`) и `resolved_arcs`
(`geom.rs:223`) считают `n - 1` от `points.len()` под защитой раннего выхода
`self.arcs.is_empty()`. Контур с `points: []`, `closed: false` и непустым `arcs`
проходит этот ранний выход и даёт `0usize - 1`. Проверено: `RuntimeError: unreachable`.

## Decision

**Дуга — часть контура, и проверяется вместе с контуром: `Contour::validate`
обязан видеть `self.arcs`, а `ArcSegment` получает собственную проверку.**

Правила дуги, минимально необходимые для того, чтобы геометрия имела смысл:

| Поле | Требование | Почему |
|---|---|---|
| `radius` | конечен и `> 0` | Радиус `0` — вырожденная кривая: опорные точки вырождаются в отрезок, а хеш и площадь получают другие значения, чем у многоугольника без дуги. Отрицательный и `NaN` — не кривая. |
| `from` | `< n` (`< n-1` для открытого контура) | Иначе дуга не начинается ни в одной точке контура. |
| `to` | `== (from + 1) mod n` | **Одна дуга заменяет ровно одно ребро.** См. «Три потребителя» ниже. |

Про замыкание: последнее ребро замкнутого контура идёт от последней точки к
нулевой, поэтому там `to = 0`, а не `to = n`. Запретить это — значит запретить
`round_corners` на шве любого замкнутого контура, то есть почти всё, что
скругляет.

Порядок проверки в `Contour::validate` — после проверки точек. Дуга не может быть
проверена, пока не подтверждено, что точки существуют.

Дополнительно:

* Молчаливый фильтр в `resolved_arcs` **остаётся**: он не нужен как защита, но он
  корректен как функция, вызываемая с уже проверенным входом. Убирать его — значит
  сломать `n - 1` на пустом контуре в момент, когда задача про панику ещё не
  закрыта. Проверка переехала туда, где вход становится валидным.
* `validate/src/lib.rs:654` теряет `expect`. Ветка «кривые есть, но радиуса нет»
  становится недостижимой **по построению**, а не по соглашению.

## Alternatives

### A. Валидировать только на границе браузера (`extract_layers`)

- **Плюсы**: не трогает доменную модель; одно место; сразу закрывает достижимость паники.
- **Минусы**: `validate()` — `pub`, `LayerInput::geometry` публично конструируем, а
  `validate_with_registration` — `pub`. Любой другой потребитель (будущий сервер,
  будущий воркер) снова получает панику. Манифест и схема продолжают принимать
  геометрию, которую ядро не может обработать.
- **Стоимость**: S. **Отвергнут** — закрывает симптом на одной из границ, оставляя
  инвариант, который сам же нарушает.

### B. Сделать `ArcSegment` непрозрачным: конструктор вместо `Deserialize`

- **Плюсы**: невозможно построить недействительную дугу в принципе.
- **Минусы**: требует `#[serde(try_from = …)]` или промежуточного типа, а также
  переработки всех мест, конструирующих дуги вручную. Меняет сигнатуру
  конструктора — публичный API ядра.
- **Стоимость**: M. **Отложен** — правильная цель, но это отдельное решение о
  конструкторах. Проверка в `validate` даёт ту же гарантию для всех входов,
  потому что всё входит через `validate`.

### C. Считать `radius <= 0` и выход индекса допустимыми

- **Плюсы**: ничего не ломается.
- **Минусы**: хеш перестаёт быть идентификатором геометрии (дефект 2 выше — уже
  воспроизведён), T-05 включается на геометрии, к которой не относится, а
  `expect` продолжает паниковать.
- **Стоимость**: 0. **Отвергнут** — это не «ослабить проверку», это оставить
  подтверждённый дефект идентичности.

## Consequences

### Positive

* `validate` перестаёт быть функцией с паникой на документе извне, и инвариант
  «Never panics» начинает держаться на типах, а не на соглашении.
* Хеш снова различает геометрию с кривой и без неё — включая случай
  недействительной дуги, который раньше совпадал.
* Модуль браузера переживает плохой вход вместо того, чтобы становиться
  непригодным.
* `geometry.holes must be clockwise` и остальные проверки контура получают
  единый порядок: точки, потом дуги.

### Negative / Trade-offs

* Появляются четыре новых варианта `GeometryError`. Любой код, который
  разбирает `GeometryError` перечислением, нужно проверить — в этом репозитории
  таких мест нет (ошибки переходят в строки), но появление вариантов ломает
  исчерпывающий `match` в будущем потребителе.
* Дуги, которые кто-то построил вручную с нулевым радиусом «чтобы посмотреть»,
  перестанут проходить. Это правильно, но это изменение поведения.
* `MAX_POINTS_PER_PATH` не ограничивает число дуг: контур с 20 000 точек может
  нести 20 000 дуг. Проверка каждой — O(n). Прямого эксплойта здесь нет (дуги
  не увеличивают точность, только длину проверки), но предел стоит ввести вместе
  с первым реальным потребителем.

* `extract_layers` (`wasm/src/lib.rs`) вызывает `validate_strict` при разборе
  геометрии. **Это оказалось частью исправления, а не отдельной задачей.**
  Проверка ядра закрыла панику внутри, но `extract_layers` десериализовал геометрию
  без всякой проверки — `measure_layer` проверял всегда, а документный путь нет.
  На пересобранном артефакте вход «контур без точек с непустым списком дуг» по-прежнему
  давал `RuntimeError: unreachable`, потому что до `resolved_arcs` доходил вход,
  который никто не проверял.
* Предел на число дуг (`MAX_ARCS_PER_PATH`), когда появится потребитель, который
  этим пользуется.
* `BUG-010` — расхождение контракта: `ArcSegment` документирует прогон `from .. to`,
  конвейер принимает только одно ребро. Математика (`arc_sweep`) многоточечные
  прогоны умеет, конвейер — нет, и ни один тест этого не замечает.

## Validation

`make check` зелёный, 394 теста (было 384).

Регрессия зафиксирована **восемью** тестами, а не одним:

| Слой | Тест | Что ловит |
|---|---|---|
| `kernel` | `an_arc_with_a_non_positive_radius_is_rejected` | BUG-001 |
| `kernel` | `a_non_finite_arc_radius_is_rejected` | нарушение обещания «NaN/Inf запрещены» |
| `kernel` | `an_arc_spanning_several_edges_is_rejected` | BUG-003, главный случай |
| `kernel` | `an_arc_reaching_past_the_last_point_is_rejected` | BUG-003 |
| `kernel` | `an_arc_starting_past_the_last_point_is_rejected` | BUG-003 |
| `kernel` | `an_empty_arc_run_is_rejected` | прогон, не рисующий ничего |
| `kernel` | `the_wrapping_arc_on_a_closed_contour_is_legal` | что правило не запрещает `round_corners` |
| `validate` | `an_arc_the_measurement_cannot_report_does_not_take_the_validator_down` | BUG-001 на уровне валидатора |
| `wasm` | `a_layer_with_arcs_and_no_points_is_refused_rather_than_trapping` | андерфлоу |
| `wasm` | `a_layer_whose_arc_has_no_radius_is_refused_with_a_reason` | путь документа |

Проверялось, что защита настоящая, а не всегда зелёная: с отключённой проверкой
дуг 5 ядерных тестов падают, а восстановление `expect` роняет тест валидатора с
`panicked at … curves exist` — то есть тест воспроизводит исходную панику, а не
имитирует её.

Эмпирическая перепроверка на пересобранном wasm-артефакте, тот же приём, которым
находки были получены:

| Вход | Было | Стало |
|---|---|---|
| `validate_project`, дуга `radius: 0` | `RuntimeError: unreachable` | `Error: layer 1 geometry: arc 0 has radius 0, which is not a curve; it must be finite and above zero` |
| `validate_project`, `points: []` + дуга | `RuntimeError: unreachable` | `Error: layer 1 geometry: contour needs at least 2 distinct points` |
| `validate_project`, `from: 2, to: 99` | `PASS` (тихо) | `Error: layer 1 geometry: arc 0 runs from point 2 to point 99 of a 4 point contour; an arc replaces exactly one edge…` |
| `measure_layer`, дуга `radius: 0` | принят молча | `Error: arc 0 has radius 0, …` |

Модуль переживает все четыре: вызовы идут в одном процессе, и последующие
работают. При панике в wasm этого не происходит — ловушка убивает инстанс.

Не входит в это решение и остаётся отдельной задачей: `radius: 1e300` проходит
проверку (он конечен и положителен) и даёт `area_mm2: null` — нечисловое измерение
(`BUG-006`).

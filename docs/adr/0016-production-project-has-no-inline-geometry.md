# ADR-0016 · Производственный Mask Project не несёт встроенной геометрии

- **Status**: ACCEPTED
- **Date**: 2026-10-06
- **Deciders**: Founder / CTO
- **Affects**: `docs/schema/mask-project.v1.json`, `docs/schema/examples/mask-project.v1.example.json`, `docs/schema/validate_examples.py`, `engine/wasm`, `docs/03_DOMAIN/MASK_PROJECT.md`
- **Principles**: P-02 (Mask Project как сущность), P-03 (геометрия — источник истины), P-08 (воспроизводимость)
- **Supersedes**: —

## Context

`mask-project.v1.json` называется полным цифровым описанием и источником истины, но
его объект `geometry` описывает только координатную рамку:

```json
{
  "design_space": {"width_mm": 1412.0, "height_mm": 1046.0},
  "transform": {"kind": "affine", "matrix": [...]},
  "units": "mm",
  "tolerance": {"flatten_mm": 0.05, "bool_epsilon_mm": 0.001}
}
```

Слой ссылается только на идентификатор:

```json
{
  "id": "L03-0b83",
  "index": 3,
  "geometry_id": "geo_L03"
}
```

Ни одно поле проекта не содержит сами векторы. В то же время браузерный вход
`validate_project` требует встроенный объект:

```json
{
  "composition": {
    "layers": [
      {
        "index": 1,
        "geometry": {
          "shapes": [
          ]
        }
      }
    ]
  }
}
```

Поэтому возникло противоречие: либо production-формат должен включать геометрию,
которую проверяет движок, либо браузер не принимает production-формат.

Ограничения:

* Решение A1: сервисного слоя и геометрохранилища сейчас нет, но откладывание не
  отменяет необходимость понимать, что документ утверждает.
* `MASK_PROJECT.md §4` уже описывает отдельный геометрический документ со ссылками
  вида `geo_L03`, а база данных описывает `inline_data` или `storage_key`.
* `fixtures` сознательно не являются Mask Project (ADR-0014) и не могут служить
  разрешением для production-формата.
* Валидатор проверяет геометрию, а не только ссылки: ссылка без доступного вектора
  не является проверкой.

«Просто добавить поле `geometry` в production-схему» недостаточно, потому что это
меняет контракт производственного формата, вводит дублирование векторов и требует
решения о версионировании, хэшировании и лимитах вложенности.

## Decision

**Производственный Mask Project остаётся метаданным документом: он содержит
координатную рамку и ссылки `geometry_id`, но не содержит встроенных векторов.
Браузерный вход `validate_project` — это отдельный оценочный пакет с обязательной
встроенной геометрией, а не валидный `mask-project.v1.json`.**

## Alternatives

### A. Добавить `geometry` в `composition.layer`

- **Плюсы**: production-документ наконец содержит проверяемую геометрию; браузерный и
  серверный входы совпадают.
- **Минусы**: меняет публичный контракт v1; дублирует крупные и часто меняющиеся
  векторы внутри метаданных; требует правил размера, хэширования и версионирования
  вложенной геометрии. Отсутствующий сервер не может предоставить ни хранение, ни
  разрешение ссылок, поэтому формат нельзя реализовать до конца.
- **Стоимость**: L: схема, примеры, движок, тесты, миграционная политика,
  служба геометрии.

### B. Создать отдельный `layer-geometry.v1.json` сейчас

- **Плюсы**: один контракт на геометрию для проекта, клипа, wasm и будущих сервисов.
- **Минусы**: доменный документ уже содержит подходящий формат в `MASK_PROJECT.md §4`,
  а независимой реализации чтения/хранения сейчас нет. Отдельная схема без
  потребителя — это документация, выдающая себя за контракт.
- **Стоимость**: M сейчас, L с реализацией хранения.

### C. Молча оставить как есть

- **Плюсы**: ноль работы.
- **Минусы**: `validate_project` остаётся с комментарием, будто принимает «тот же
  JSON Mask Project», а production-пример не может пройти ни один путь проверки.
  Потребитель верит, что проверяет production-документ, и проверяет другой.
- **Стоимость**: нулевая сейчас, отказ в продакшене потом.
- **Почему отвергнут**: ложное соответствие хуже явного разрыва.

## Consequences

### Positive

* Production-формат перестаёт утверждать, что содержит проверяемую геометрию.
* Браузерный вход получает имя и границу: это оценочный пакет, а не проект.
* Неполнота становится проверяемой: у слоя проекта есть ссылка, но нет векторов;
  а оценочный пакет без векторов отвергается до проверки.
* Никакого дублирования векторов в v1 и никакого выдуманного хранилища.

### Negative / Trade-offs

* Production-документ по-прежнему нельзя напрямую загрузить в браузерный
  валидатор без подготовки оценочного пакета.
* Будущему серверу всё равно потребуется хранилище геометрии и правило
  разрешения `geometry_id`; это решение не создаёт его, а только не врёт о нём.
* Терминология расходится намеренно: «проект» без геометрии неполон, и неполнота
  отмечена, а не исправлена.

### Follow-up

* Отдельная геометрическая схема и хранилище, когда появится сервис.
* Правило, какой документ считается воспроизводимым без векторов, а какой — только
  с ними.
* Обновление процесса ADR: таблица обязательных решений до сих пор перечисляет
  `ADR-0014` и `ADR-0015` под старыми темами, хотя файлы заняты другими решениями.

## Validation

Как проверяем, что решение верное. Критерий успеха:

1. `mask-project.v1.json` прямо говорит, что `geometry` — это рамка координат, а
   `geometry_id` — ссылка на отдельный векторный документ.
2. Валидный пример `mask-project.v1.example.json` содержит только `geometry_id` и
   проходит схему.
3. `validate_examples.py` отвергает документ, добавляющий встроенный `geometry` в
   слой проекта, потому что production-контракт не принимает векторы.
4. Браузерный вход больше не называет себя «тем же Mask Project JSON»: его
   документация и тесты отличают оценочный пакет от production-документа.

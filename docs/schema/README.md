# Контракты данных v1

Машино-проверяемые схемы. Ядро читает и пишет по ним, а не по договорённости.

## Файлы

| Файл | Что описывает |
|---|---|
| `mask-project.v1.json` | Mask Project — источник истины (`MASK_PROJECT.md`) |
| `manifest.v1.json` | Production Manifest — то, что читает сторонний производитель |
| `fixture.v1.json` | Фикстура — исходная геометрия, которую читает `maskctl`. **Не** Mask Project, см. ADR-0014 |
| `examples/mask-project.v1.example.json` | Валидный пример проекта |
| `examples/manifest.v1.example.json` | Валидный пример манифеста |
| `validate_examples.py` | Проверка схем и примеров, включая негативные случаи |

## Проверка

```bash
python3 docs/schema/validate_examples.py
```

Скрипт проверяет не только примеры, но и **все** файлы в `engine/fixtures/`:
фикстура, формат которой никем не описан, — это не контракт.

Требуется `jsonschema` (`pip install jsonschema`). Скрипт проверяет:

1. Сами схемы валидны по Draft 2020-12.
2. Примеры проходят валидацию.
3. **Инварианты действительно отвергают плохие документы.**

Третий пункт важнее первых двух: схема, которая принимает всё, хуже чем её
отсутствие — она создаёт ложную уверенность.

## Что выражено в схеме, а что нет

| Проверка | Где enforced |
|---|---|
| Формат `MASK-000127`, `RUN-000001`, кодов слоёв и плиток | JSON Schema `pattern` |
| Единицы измерения только `mm` | `const` |
| Диапазоны: индекс слоя 1–64, ≤ 64 слоёв, fidelity 0–1 | JSON Schema |
| Перечислимые значения: статус, роль, тип отношения, вердикт, severity | `enum` |
| I-5: `PASS` ⇒ `violations_error = 0` | `allOf` / `if-then` |
| Запрет растягивания по габаритам | `scale_policy` без значения `stretch` |
| Наличие `physical_proof` и `effective_limits` в манифесте | `required` |
| `performed: true` ⇒ обязательна дата | `if-then` |
| I-2: уникальность индекса слоя в ревизии | **не** JSON Schema — constraint БД + Validator |
| I-3: ацикличность графа слоёв | **не** JSON Schema — `Validator` |
| I-6: манифест ⇔ артефакты | **не** JSON Schema — транзакция |
| I-7: снимки профилей в ревизии | **не** JSON Schema — транзакция |
| Геометрическая корректность | **не** JSON Schema — `Topology Engine` |
| Производимость | **не** JSON Schema — `Manufacturing Validator` |
| Список кодов правил в `_expect` фикстуры | **не** JSON Schema — `RuleSet` и тест `every_fixture_does_what_it_claims` |
| Геометрия фикстуры: замыкание, ориентация, самопересечения | **не** JSON Schema — `Topology Engine` |

**Принцип:** схема описывает форму, а не смысл. Проверка смысла — работа
детерминированного ядра. Схема не должна пытаться дублировать `Validator`,
иначе появится второй источник истины.

## Версионирование

`schema_version` и `manifest_version` — целые числа, первая версия = `1`.
Правила:

* В рамках версии схемы меняются только **обратно совместимо**.
* Удаление поля или изменение его типа → новая версия.
* Проект со `schema_version` новее, чем понимает движок → `FATAL`
  («Формат проекта vN не поддерживается этой версией движка»).

## Известные ограничения примеров

Пример проекта содержит **три** слоя из шести, чтобы оставаться читаемым.
Это допустимо: `minItems` = 1, инвариант I-1 требует хотя бы один слой.
Полный шестислойной Mask Project не появится из фикстур: фикстура — другой
формат (ADR-0014), и шесть слоёв покрывает `engine/fixtures/t5_six_layers.json`
как вход геометрии.
